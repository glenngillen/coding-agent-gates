# Order service: working rules

This repository is a small order service. Money is integer cents. The public
interface is `OrderController` in `src/orders/controllers/orders.py`, built by
`build_app()` in `src/orders/wiring.py`.

## Architecture

- `src/orders/controllers/` decodes requests, calls the application service
  and maps its results to responses. Controller modules must not import
  anything from `orders.infrastructure`. Reach storage only through the
  application layer.
- Business decisions belong in `src/orders/application/`: pricing, discount
  eligibility, which orders qualify for something, status-change rules and
  business limits on what may be ordered. A controller must not make these
  decisions, even with data the service returns to it. Checking that a request
  has the right shape and types is the controller's job.
- `src/orders/infrastructure/` holds storage (an in-memory repository). Only
  the application layer uses it.
- `src/orders/domain.py` holds plain data shared by every layer.
- `src/orders/wiring.py` is the one place that constructs every layer.
