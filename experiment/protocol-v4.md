# Study protocol (version 4): a lean prompt with a gate, or a large handbook?

**Frozen 2026-11-20, before any version 4 session.** The inputs listed under
"What is frozen" are hashed in `v4/frozen-manifest.json`. The runner refuses to
start if they, or the version 2 and version 3 inputs they build on, have
changed (`tools/run_study_v4.py freeze --check`).

## Why a fourth study

Version 3 (`results-v3.md`) found that a one-line hint in `CLAUDE.md` was
enough to keep the import rule (0 of 24 sessions slipped), and that a gate
caught and repaired every slip when nothing was written down. Exploratory
probes afterwards (`runs/exploratory-v3-2026-11-20/probes.json`, not study
data) used a generated instruction file of about 40,000 tokens: no slips in 14
sessions, and Sonnet sessions that cost about twice as much as usual.

Those probes were two sessions per condition. This study measures the
comparison properly: **what does a large instruction file cost per session,
and does it buy anything a lean prompt with a gate does not?**

Descriptive only. No expected outcome is fixed and no hypothesis test is run.

## Design

Version 3's design with different guidance levels.

| Guidance | `CLAUDE.md` |
| --- | --- |
| `one-line` | `v4/instructions/one-line.md`, byte-identical to version 3's one-line level (581 characters). The Architecture section is one sentence: "The code is layered: controllers, application, infrastructure and domain. Keep to the layering." |
| `handbook` | `v4/instructions/handbook.md`, 162,000 characters, generated by `tools/make_handbook.py`: fifteen general sections (logging, testing, security, migrations and so on) and templated per-team service rules, with version 2's full Architecture section, verbatim, about 60% of the way down. |

The handbook states the rule more fully than the lean file does: it carries
the whole Architecture section, including where business decisions belong.

- **Arms:** A (no gate) and B (the import-contract sensor on every `Stop`, up
  to 3 repair requests per turn), as in version 3.
- **Cells:** 2 guidance levels × 2 scenarios × 2 agent configurations × 2 arms
  = 16 cells. **Sessions:** 3 repeats per cell = **48**, 192 planned turns.
- **Order:** planned before any session with the frozen seed 2026112004,
  shuffled within each repeat block; four sessions at a time.

Everything else is versions 2 and 3, reused unchanged: scenarios, workspace
and history, contracts, acceptance tests, evaluator, Stop hook, session
driver, agent configurations, tools, permissions and isolation.
`run_study_v4.py` only points version 3's runner at `v4/study.json`.

## Measurements and reporting (fixed now)

As in `protocol-v3.md`, for each guidance level × arm, pooled and by agent
configuration:

- **Cost and time:** CLI-reported agent cost per session (total and mean) and
  median session wall time. This is the primary outcome here.
- **Structural:** sessions with a slip, caught and repaired slips, final
  structural violations, with exact one-sided 95% bounds.
- **Behaviour:** steps accepted.
- **Semantic:** the evaluation judge's verdict on the final controllers,
  counted per cell. Judge outputs, not human labels.
- Censored, cut-short and not-started sessions are counted and listed.
- `experiment/results-v4.md` is written from the retained records by
  `tools/summarize_v4.py`. The design is not changed after seeing results.

Costs are API-equivalent figures reported by the CLI, notional under a
subscription login. They include prompt-caching discounts as the CLI applied
them; sessions run four at a time and do not share a cache deliberately.

## Running it

```sh
.venv/bin/python experiment/tools/run_study_v4.py freeze --check
.venv/bin/python experiment/tools/run_study_v4.py plan --study handbook-v4-2026-11-20
```

## Limitations fixed in advance

- The handbook is generated. Its rules are plausible but templated and
  repetitive, and none of them competes with the import rule. A real
  handbook's cost per token is the same; its effect on behaviour may not be.
- One handbook size, one position for the rule. Cost scales with size; this
  measures one point.
- Cost depends on prompt caching, which depends on how sessions are spaced.
  A team's real figure will differ; the direction (a larger prompt is paid for
  on every request) will not.
- Two scenarios, three repeats per cell, two agent configurations, one
  machine, no seed, short four-step sessions.
